# LARAVEL_RULES.md

## Назначение

Этот файл содержит технические правила разработки именно для Laravel-части проекта.

Правила должны быть конкретными и проверяемыми. При изменении структуры проекта сначала сверяйся с этим файлом и сохраняй существующие договорённости, если задача явно не требует их изменения.

## JavaScript

- JavaScript хранится в `resources/js/`.
- Inline JavaScript внутри Blade-файлов запрещён.
- Не добавляй `onclick`, `onchange` и другие inline-обработчики в Blade.
- Поведение интерфейса реализуется в JS-модулях и собирается через Vite.
- Общая точка входа frontend-кода — `resources/js/app.js`.
- Код отдельной крупной функции можно выносить в отдельный модуль внутри `resources/js/` и подключать из точки входа.
- Не дублируй один и тот же JS-код в нескольких представлениях.

## Vite

- Для frontend используется Laravel Vite.
- Точки входа объявляются в `vite.config.js`.
- Production-сборка выполняется командой `npm run build`.
- Не добавляй ручную минификацию или другой сборщик без отдельной необходимости.

## CSS и мобильная адаптация

- Основные стили хранятся в `resources/css/`.
- Стили собираются через Vite.
- Любой новый или изменённый интерфейс сразу адаптируется под мобильные устройства.
- Мобильная адаптация является частью задачи, а не отдельным последующим этапом.

## Blade и компоненты

- Blade отвечает за разметку и отображение данных.
- Общая разметка выносится в layouts и Blade-компоненты.
- Повторяющиеся элементы интерфейса не копируются между страницами.
- Переиспользуемые элементы выносятся в компоненты.
- Бизнес-логику не помещай в Blade.

## Views

- Представления находятся в `resources/views/`.
- Представления инструментов находятся в `resources/views/tools/`.
- Названия views должны соответствовать назначению и текущей структуре маршрутов.

## Controllers

- Контроллеры находятся в `app/Http/Controllers/`.
- Для связанных инструментов используется понятная вложенная структура каталогов.
- Контроллер принимает запрос, подготавливает данные и передаёт их представлению.
- По мере роста бизнес-логики выноси её из контроллера в подходящие классы/сервисы.

## Routes

- Маршруты находятся в каталоге `routes/`.
- Используй именованные маршруты там, где на них есть программные ссылки.
- Бизнес-логику не помещай непосредственно в определения маршрутов, кроме простых случаев.

## Composer, Artisan и окружение

- Перед вызовом `php artisan`, которому нужны зависимости приложения, должны быть установлены Composer-зависимости.
- Для установки зависимостей используется `composer install`.
- `vendor/` не коммитится в репозиторий.
- Файлы окружения и секреты не коммитятся.
- Не храните значения production-секретов в исходниках или документации.

## Database и storage

- Изменения схемы базы данных выполняются через миграции.
- Локальная SQLite-база не коммитится, если задача явно не требует обратного.
- Каталоги, в которые Laravel должен писать на production, должны иметь корректные права доступа.

## Tests

- Существенную серверную логику сопровождай тестами.
- CI должен запускать тестовый набор перед production-деплоем.
- При изменении поведения обновляй соответствующие тесты.

## Проверка перед коммитом

Перед коммитом проверь:

1. JS не появился внутри Blade.
2. Новый UI адаптирован под мобильные устройства.
3. Повторяющаяся разметка вынесена в компоненты.
4. README просмотрен и обновлён, если изменение заметно пользователю.
