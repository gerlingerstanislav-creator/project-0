# Правила работы с Laravel

Этот файл содержит технические правила и договорённости именно для Laravel-части проекта.

## JavaScript

- Весь JavaScript хранится в `resources/js/`.
- JavaScript-код не размещаем inline внутри Blade-файлов.
- Используем Vite как штатный сборщик проекта.
- Для поведения интерфейса создаём и изменяем JS-файлы в `resources/js/`, а затем подключаем их через Vite.
- Повторно используемый JavaScript держим в отдельных модулях, когда код начинает использоваться в нескольких местах.

## CSS

- Основные стили храним в `resources/css/`.
- Стили подключаем и собираем через Vite.
- При добавлении любого нового интерфейса сразу проверяем мобильную версию.

## Blade и компоненты

- Общую разметку страниц выносим в Blade-компоненты и layouts.
- Повторяющиеся элементы интерфейса не копируем между страницами: выносим их в переиспользуемые компоненты.
- Страницы конкретных инструментов храним в `resources/views/`.
- Логику приложения не помещаем в Blade: Blade отвечает за представление.

## Контроллеры

- Контроллеры храним в `app/Http/Controllers/`.
- Контроллер отвечает за обработку HTTP-запроса и подготовку данных для представления.
- Для связанных инструментов используем отдельные контроллеры и понятную структуру каталогов.

## Маршруты

- HTTP-маршруты храним в соответствующем файле каталога `routes/`.
- Имена маршрутов задаём явно там, где они используются в приложении.
- Не помещаем бизнес-логику в определения маршрутов, кроме действительно простых случаев.

## Artisan и зависимости

- Перед любым вызовом `php artisan`, которому нужны Composer-зависимости, сначала выполняем `composer install`.
- Не коммитим `vendor/` и другие генерируемые зависимости, если это не требуется отдельно.
- Конфигурацию окружения и секреты не храним в репозитории.

## Тесты

- Новую существенную серверную логику сопровождаем тестами.
- Перед деплоем CI должен выполнять тестовый набор проекта.
