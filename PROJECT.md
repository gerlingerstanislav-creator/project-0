# Правила проекта

Этот файл содержит общие правила ведения проекта. Технические правила именно Laravel находятся в [LARAVEL_RULES.md](LARAVEL_RULES.md).

## README.md

- Перед каждым коммитом обязательно открываем и просматриваем `README.md`.
- Ищем, что изменилось в проекте с точки зрения пользователя и что стоит кратко добавить или уточнить в README.
- Если изменение влияет на разделы, назначение, пользовательский интерфейс или заметное поведение приложения, обновляем `README.md` в том же коммите.
- README должен оставаться кратким, понятным и ориентированным на пользователя проекта, а не превращаться в техническую документацию для разработчика.
- При добавлении нового инструмента или пользовательского раздела добавляем его краткое описание в README.

## Коммиты

- Одна логическая задача или один объект изменения — один коммит.
- Если для задачи меняется несколько файлов, все эти изменения делаем одним коммитом.
- Не дробим одну небольшую задачу на несколько последовательных коммитов только из-за количества изменённых файлов.

## Интерфейс

- Любой новый или изменённый интерфейс сразу адаптируем под мобильные устройства.
- Основной язык пользовательского интерфейса — русский.
- Стиль интерфейса держим единообразным: аккуратная типографика, понятная навигация, минимум лишних элементов.

## Структура

- Переиспользуемые элементы интерфейса не дублируем: выносим их в компоненты.
- Логика, представление, стили и JavaScript должны находиться в соответствующих слоях проекта.
- Правила Laravel и технические договорённости храним в `LARAVEL_RULES.md`, а общие правила проекта — здесь.

## Документация

- Документация должна описывать актуальное состояние проекта.
- Не добавляем в пользовательский README внутренние правила, секреты, пароли, IP-адреса и другую служебную информацию.
