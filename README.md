# project-0

**project-0** — веб-приложение на Laravel 13 с небольшими инструментами в едином SPA-интерфейсе.

**Сайт:** https://project-0.duckdns.org

## Доступ и авторизация

Главная страница `/` доступна без авторизации и содержит приветственное сообщение со ссылкой на вход. Все инструменты, тесты, дизайн-система и push-endpoints защищены middleware `auth`.

В системе три роли: **admin**, **moderator** и **user**. Администратор и модератор могут редактировать идеи стартапов. Начальный пользователь `user` создаётся сидером с паролем `12345678`.

## Возможности

После авторизации в боковом меню доступны следующие разделы:

1. **Идеи стартапов** — список идей из SQLite. Роли **admin** и **moderator** могут редактировать название и описание.
2. **Степан, выпей** — интерактивная мини-игра: бутылку нужно открыть, при наливании она наклоняется горлышком к стакану, пиво переливается порциями, стакан выпивается целиком одним кликом, а после опустошения слева автоматически появляется новая бутылка, а пустая остаётся на месте.
3. **Инструмент 3** — каркас третьего инструмента.
4. **Менеджерские шпаргалки** — материалы из базы данных в раскрывающихся карточках.
5. **Горнолыжные курорты** — /ski-resort с погодой, прогнозом и веб-камерами пяти российских курортов.
6. **Новости** — агрегатор RSS-лент из нескольких источников с категориями, оценкой значимости и персональной релевантности. Лента учитывает пользовательские оценки «Больше такого» и «Не интересно», позволяет скрывать источники, автоматически переводит англоязычные новости на русский через Laravel-пакет `minhyung/laravel-translator` с self-hosted LibreTranslate и показывает сначала самые новые публикации. Переводы выполняются асинхронно через очередь и не блокируют загрузку страницы.
7. **Тесты** — /tests для проверки PWA и push-уведомлений; доступна только после авторизации.
8. **Конструктор расписаний** — /cron-scheduler: простой конструктор cron-выражений и расширенный режим с несколькими правилами, валидацией, описанием и ближайшими запусками.
9. **Привет, Олег** — праздничный цветной баннер.
10. **Ура, Аня приехала!!!** — праздничная страница с большой надписью, объёмным букетом с гортензиями и постоянной мягкой анимацией цветов, листьев и декоративных элементов.

Публичные страницы — только `/` и `/login`. Остальные разделы требуют авторизации.

### Новости

Новостная страница собирает RSS из TechCrunch, Ars Technica, Habr, Hacker News, The Guardian и BBC. Запросы выполняются параллельно с короткими таймаутами, а результат кэшируется на 5 минут.

Лента разделяет **значимость** и **релевантность**: значимость оценивается по признакам изменения рынка, продукта, регулирования, безопасности и другим сигналам, а релевантность — по базовому профилю интересов и пользовательской обратной связи. «Больше такого» и «Не интересно» корректируют релевантность похожих материалов, а «Скрыть источник» исключает источник из персональной ленты. Пользователь может выбрать категории и минимальный порог значимости; эти фильтры сохраняются в профиле пользователя и автоматически восстанавливаются при следующем входе в раздел. Новости отображаются по дате публикации, от новых к старым. Англоязычные заголовки и описания переводятся асинхронно через очередь Laravel и self-hosted LibreTranslate. Переводы отдельных статей кэшируются на 30 дней; пока перевод не готов, статья сразу показывается на оригинальном языке, а страница периодически обновляет только новости до получения готовых переводов. Очередь обслуживается отдельным systemd worker на VPS. Политические новости не ранжируются по политическим предпочтениям; учитываются тема и общественная значимость.

## Архитектура

Frontend построен на **Inertia.js + Vue 3** и все пользовательские страницы рендерятся как Inertia/Vue-компоненты; Blade используется только как минимальный HTML-shell:

- Laravel отвечает за маршруты, авторизацию, данные и серверные mutations.
- Inertia передаёт страницы и props без отдельного frontend API.
- Vue-компоненты находятся в resources/js/pages/.
- Общий интерфейс находится в resources/js/layouts/.
- Точка входа frontend — resources/js/app.js.
- Стили — resources/css/.

### Design system

Интерфейс использует внутреннюю дизайн-систему на базе semantic design tokens и переиспользуемых Vue-компонентов. Основные компоненты находятся в `resources/js/components/ui/`, токены и базовые стили — в `resources/css/design-system/`. Каталог компонентов доступен на `/design-system`. При создании или изменении интерфейса сначала используй существующие компоненты и токены, а новые повторяющиеся паттерны выноси в дизайн-систему.

PWA и Web Push уже реализованы:

- public/site.webmanifest;
- public/sw.js;
- resources/js/pwa.js;
- модель и миграция PushSubscription;
- защищённые endpoints /push/subscriptions.

Разрешение на уведомления запрашивается по действию пользователя. Production-деплой автоматически генерирует VAPID-ключи на VPS, если они ещё не заданы, а серверный Web Push sender отправляет уведомления через Minishlink WebPush.

## Локальный запуск

Установить зависимости:

~~~bash
composer install
npm install
~~~

Подготовить окружение и SQLite:

~~~bash
cp .env.example .env
touch database/database.sqlite
php artisan key:generate
php artisan migrate --seed
~~~

Запустить dev-сервер frontend:

~~~bash
npm run dev
~~~

Production-сборка:

~~~bash
npm run build
~~~

Тесты:

~~~bash
vendor/bin/phpunit
~~~

Тестовый набор использует SQLite в памяти и автоматически применяет миграции через `RefreshDatabase`.

## CI/CD

Push в main запускает GitHub Actions. Feature-тесты учитывают текущую модель доступа: защищённые разделы проверяются как для гостя, так и для авторизованного пользователя.

Pipeline выполняет:

1. PHP 8.5 и PHPUnit.
2. Node.js 22 и production-сборку Vite.
3. Упаковку release-архива.
4. Деплой на Ubuntu VPS после успешных проверок.
5. HTTPS health check /up.
6. VAPID health check.
7. Push-уведомление администратору после успешного деплоя.
8. Telegram-уведомление при ошибке push-деплоя.

Деплой выполняется из release-архива и не переносит локальные .env, SQLite-базу, vendor или node_modules.

### Диагностика production БД

Для безопасной проверки production SQLite добавлена read-only диагностика `php artisan project:db-diagnostics --json`. Она показывает состояние соединения, список таблиц, миграции, распределение ролей, количество записей основных таблиц и состояние Web Push, но не выводит пароли, push endpoint, ключи подписок или секреты. Запуск через GitHub Actions доступен вручную или командой `/db-diagnose` в issue репозитория от владельца репозитория.
